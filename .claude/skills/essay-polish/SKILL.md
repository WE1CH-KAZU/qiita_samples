# 論考・エッセイ 推敲スキル

著者が加筆・練り上げた後の記事に対して、Claudeが再び編集を担うスキルです。

**このスキルが前提とすること：**
著者はすでに主張・自己開示・具体例・固有語彙を記事に盛り込んでいます。Claudeはそれらを**一切変えず**、構造・論理の流れ・文体のリズムだけを整えます。

---

## 依頼方法

### 方法1：推敲依頼ブロック（推奨）

記事内の書きかけ・意図だけ書いた箇所を、以下の形式でマークしてください。

~~~
``` 推敲依頼
ここに著者のメモ・意図・引用したいものを書く。
例：「西遊記の一節（悟空が筋斗雲でどこまでも飛んでも菩薩の手の中）を引用し、
思考の射程の比喩としてつなげたい。」
```
~~~

Claudeはブロック内の意図を読み取り、**そのブロックを置き換える実際の文章**を提案します。著者の意図・語彙・語り口を最大限に引き継ぎます。

### 方法2：セクション指定

特定のセクションだけを対象にしたい場合、以下のように指示します。

```
## セクション名「〇〇」の推敲をしてほしい。
論理の流れが弱い気がする。
```

Claudeはそのセクションのみを対象に、論理的整合性とリズムを整えます。

### 方法3：ファイル全体のリズム・構造チェック

ファイルパスまたは全文を渡して「全体を見てほしい」と指示します。文章の内容ではなく、**節の順序・論の流れ・長短のリズム**の観点でフィードバックします（書き直しは行わず、提案のみ）。

---

## エッセイのスタイル基準

推敲時にClaudeが目標とするスタイルの基準。「Claudeが編集してよいもの」はこの基準に沿って整える。

### 文体の基調

- **ます調を基調**とする。核心の断言では「〜にある」「〜からしか生まれない」などだ体を混ぜてよい
- 文末を統一する必要はなく、論のリズムで選ぶ

### 主語と人称

- 一人称は「**僕**」を使う
- 「**僕たち**」への切り替えは論の早い段階から行ってよい。読者を傍観者にさせず、共有の問いとして引き込む
- 締めは個人の確信として引き取る。その記事で一番言い切りたいことを最後に置くことを優先する

### 断言と問いかけのバランス

- 断言（「〜にある」「〜必要がある」）と問いかけ（「〜ではないでしょうか」）を混在させる
- 「そろそろ」など口語的な緩衝語を挟み、断言が攻撃的・説教的にならないようにする
- **核心部分では逃げない**：曖昧な言い回しでぼかさず、思考をそのまま文章化する

### リズムと文の長さ

- 長い文で論理を積み上げた後、短文一発で封をする
- 同じ文末構造を繰り返すことで推進力を作る

### 強い言葉の扱い

- 大きな言葉を使うときは引用符を付けるなど、言葉の重さを自覚しながら使う誠実さを示す

### 参考資料

- 末尾に参考資料セクションを設ける
- 著者が実際に読んだ書籍・記事を挙げる（URLではなくタイトルで可）

### 差別化の核

- 著者のパーソナリティはデータアナリスト。データサイエンス・統計の概念（例：律速要素、尤度、非自明さ）を思考論・AI論の議論の枠組みとして借用する
- 「AIはすごいが人間も大切」という曖昧な落とし所に逃げない
- 自分のパーソナリティや経験に根ざさない抽象論にしない

---

## Claudeが絶対に変えないもの

以下は著者の声・パーソナリティの核です。編集対象外とします。

- 著者の自己開示・経験への言及（「僕もこの恩恵に預かっている身だから」など）
- 著者の実務経験から来る具体例・固有名詞（HAZOP、N1分析など）
- 著者が選んだ語彙・表現・言い回し
- 著者が断言している箇所の強度（断言を柔らかくしない）
- 参考資料セクションの内容

---

## Claudeが編集してよいもの

- **論理の接続**：節と節の橋渡し、前の節との矛盾の解消
- **リズム**：長文が続いた後の短文挿入、文末の単調さの解消
- **推敲依頼ブロックの文章化**：著者メモを実際の文章に変換
- **冗長な言い回しの整理**：意味を変えずに読みやすくする

---

## 出力形式

### 推敲依頼ブロックへの対応

```
【推敲依頼ブロック（〇〇節）への提案】

---
（ここに提案文を記載）
---

変更の意図：[著者のメモのどの意図を、どう文章化したか]
```

### セクション・全体への対応

```
【推敲提案】

対象：〇〇節 / 全体

変更箇所：
- [変更前] → [変更後]（意図：〇〇）

変えなかった箇所・理由：
- [著者の声として保護した箇所と理由]
```
