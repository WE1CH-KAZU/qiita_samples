# 技術記事 構成設計

記事を書く前に、骨格となる構成（アウトライン）をユーザーとともに設計します。
各セクションをひとつずつ対話形式で確認しながら固めることで、論理的で読みやすい記事を作れます。

**進め方**: ユーザーの考えや情報を受け取ってから各セクションの案を生成します。各セクションでユーザーの「OK」を受けてから次へ進んでください。修正指示があれば再生成して再確認します。

---

## フェーズ0: 基本情報の収集

`$ARGUMENTS` に情報が渡されていればそれを使用する。不足している場合は以下をまとめて1回で質問する。

質問例:
> 以下の3点を教えてください。
> 1. **テーマ/トピック**: どんな技術・手法についての記事ですか？
> 2. **記事の種類**: 概念解説 / チュートリアル / 比較考察 / 事例紹介 / その他
> 3. **おおよその文量**: 短め（2000字以内）/ 標準（3000〜5000字）/ 詳細（5000字以上）

回答を受け取ったら、フェーズ1へ進む。

---

## フェーズ1: 対象読者

### 質問する

> 対象読者のイメージを教えてください。
> - どんな職種・ロールの人ですか？（例: データアナリスト、バックエンドエンジニア）
> - スキルレベルは？（例: 業務経験1〜2年、Python基礎は知っているが統計は初めて）
> - この記事を読む目的・動機は？

### 生成する

ユーザーの入力をもとに、以下の形式で `## 対象読者` セクションの案を生成する。

```
## 対象読者

- [職種・ロール]
- [スキルレベルの具体的な描写]
- [この記事を読む動機・目的]
```

### 確認する

案を提示した後、以下のように確認する。

> この対象読者でよいですか？修正があればお知らせください。OKであれば次のセクションへ進みます。

OKを受けたらフェーズ2へ進む。

---

## フェーズ2: 記事で得られること（課題フロー）

### 質問する

> 読者が直面している課題や、この記事で紹介する解決策についてお聞かせください。
> 以下の観点で教えていただけると助かります（思いつく範囲でOKです）。
> - 読者が業務で困っていること（痛点・課題）
> - その課題を解決するための方針・アプローチ
> - 解決しようとすると直面する技術的な壁
> - この記事の手法がどうその壁を突破するか

### 生成する

ユーザーの入力をもとに、4項目を埋めて以下の形式で生成する。

```
## 記事で得られること

読者が直面している課題から、この記事の価値を以下の流れで示す。

- **最大の課題**: [対象読者が業務で直面している、最も大きな問題・痛点]
- **課題を解決するための手段**: [その課題を解決するアプローチ・方針]
- **手段を実行するための障壁**: [手段を実行しようとしたときに立ちはだかる技術的・実務的なハードル]
- **障壁を突破するツール**: [この記事で紹介する分析手法・技術が、その障壁をどう突破するか]
```

### 確認する

> この課題フローでよいですか？修正があればお知らせください。OKであれば章構成へ進みます。

OKを受けたらフェーズ3へ進む。

---

## フェーズ3: 章構成（1章ずつ）

章を1章ずつ対話で設計する。まず「はじめに」から始め、続いて本文の各章、最後に「まとめ」「参考文献」を扱う。

### 各章の進め方

以下を章ごとに繰り返す。

**ステップA: ユーザーの考えを聞く**

> 第N章に含めたい内容・アイデアはありますか？
> なければ「提案して」と言っていただければ Claude が案を出します。

**ステップB: 章の案を生成する**

ユーザーの入力（または「提案して」の指示）をもとに、以下の形式で章の案を生成する。

```
### 第N章: [章タイトル]

- ポイント:
  - [サブポイント1]
  - [サブポイント2]
- 難易度: 入門 / 中級 / 上級
- 含める要素: 概念説明 / `.py` ファイル参照 / 図解 / 事例 など
```

分析手法の核心を扱う章では、ポイントの中に以下のような接続文の案を含める。
「〇〇という特性があるからこそ、△△という障壁を乗り越えられ、□□の実行が現実的になる」という因果を1〜2文で示す。

**ステップC: 確認する**

> この章の案でよいですか？修正があればお知らせください。OKであれば次の章へ進みます。

OKを受けたら次の章へ。

### 「はじめに」の扱い

「はじめに」はフェーズ2の課題フローを活用して Claude が案を生成する（ユーザーへの質問は省略してよい）。

必須要素:
- テーマの技術を活用するシーンの提示（読者の状況への同調）
- 課題との接続文: 「最大の課題」→「解決手段」→「障壁」→「この記事の分析手法が障壁を突破する」という流れを1〜2文の自然な語りで示す

### 「まとめ」「参考文献」の扱い

本文の全章が確定した後にまとめて提示する。

```
### まとめ

- 整理する内容: [各章の要点]
- 次のステップ: [発展的な学習先]

### 参考文献

- 想定される参照先: [論文・ドキュメント・記事など]
```

### 全章確認後

全章の案が出揃ったら確認する。

> 以上で章構成の案が揃いました。追加・削除したい章はありますか？なければタイトル案に進みます。

OKを受けたらフェーズ4へ進む。

---

## フェーズ4: タイトル案

これまでに確定した情報（テーマ・対象読者・課題フロー・章構成）をもとに、タイトル案を3つ生成して提示する。

```
## タイトル案

1. [タイトル案1]
2. [タイトル案2]
3. [タイトル案3]
```

> 気に入ったタイトルはありますか？修正や別案の追加があればお知らせください。

確定したらフェーズ5へ進む。

---

## フェーズ5: 最終アウトライン出力

確定した全セクションをまとめて以下の形式で出力する。

```
# [確定タイトル]

## 記事の種類
[確定内容: 概念解説 / チュートリアル / 比較考察 / 事例紹介 / その他]

## 対象読者
[確定内容]

## 記事で得られること
[確定内容]

## 章構成

### はじめに
[確定内容]

### 第1章: [タイトル]
[確定内容]

### 第2章: [タイトル]
[確定内容]

（以降、確定した章を続ける）

### まとめ
[確定内容]

### 参考文献
[確定内容]

## 章間の流れ
[各章がどのように繋がっているかの説明]

## 注意点・難所
[書く際に注意が必要な点、技術的に難しい説明箇所など]
```

出力後、以下の確認をする。

> このアウトラインで `/write-article` を使って記事を生成しますか？

$ARGUMENTS
