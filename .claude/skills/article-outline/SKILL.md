# 技術記事 構成設計

記事を書く前に、骨格となる構成（アウトライン）を設計します。記事本文を書く前にこのSKILLで構成を固めることで、論理的で読みやすい記事を作れます。

## 動作手順

### ステップ1: 情報収集

以下を確認してください。引数として渡された場合はそれを使用し、不足している場合は質問してください。

- **テーマ/トピック**
- **対象読者**（スキルレベル・職種・目的）
- **記事の種類**: 概念解説 / チュートリアル / 比較考察 / 事例紹介 / その他
- **おおよその文量**: 短め（2000字以内）/ 標準（3000〜5000字）/ 詳細（5000字以上）

### ステップ2: アウトライン生成

以下の形式でアウトラインを出力してください。

---

## アウトライン出力形式

```
# [記事タイトル案（複数案）]

## 対象読者
- [具体的な読者像]

## 記事で得られること

読者が直面している課題から、この記事の価値を以下の流れで示す。

- **最大の課題**: [対象読者が業務で直面している、最も大きな問題・痛点]
- **課題を解決するための手段**: [その課題を解決するアプローチ・方針]
- **手段を実行するための障壁**: [手段を実行しようとしたときに立ちはだかる技術的・実務的なハードル]
- **障壁を突破するツール**: [この記事で紹介する分析手法・技術が、その障壁をどう突破するか]

## 章構成

### はじめに
- ポイント: [記載すべき内容の箇条書き]
- 目的: 読者の興味を引き、記事の価値を示す
- シチュエーション提示: テーマの技術を活用するシーンを提示し、同じような分析課題を持つ読者へ同調する
- 課題との接続文（必須）: 「最大の課題」→「解決手段」→「障壁」→「この記事の分析手法が障壁を突破する」という流れを1〜2文の自然な語りで示す。読者に「この分析を使えば、自分の課題が解決できる」と感じさせることが目的

### 第1章: [章タイトル]
- ポイント:
  - [サブポイント1]
  - [サブポイント2]
- 難易度: 入門 / 中級 / 上級
- 含める要素: 概念説明 / `.py` ファイル参照 / 図解 / 事例 など

### 第2章: [章タイトル]
- ポイント:
  - [サブポイント1]
  - [サブポイント2]
- 難易度: 入門 / 中級 / 上級
- 含める要素: 概念説明 / `.py` ファイル参照 / 図解 / 事例 など

（※ 分析手法の核心を扱う章には、技術説明の前後に以下のような接続文を差し込むこと。技術の凄さを語るのではなく、「この機能があるから障壁が消え、解決手段が実行できるようになる」という因果を1〜2文で示す。例：「〇〇という特性があるからこそ、△△という障壁を乗り越えられ、□□の実行が現実的になる」）

### まとめ
- 整理する内容: [各章の要点]
- 次のステップ: [発展的な学習先]

### 参考文献
- 想定される参照先: [論文・ドキュメント・記事など]

## 章間の流れ
[各章がどのように繋がっているかの説明]

## 注意点・難所
[書く際に注意が必要な点、技術的に難しい説明箇所など]

## タイトル案
1. [タイトル案1]
2. [タイトル案2]
3. [タイトル案3]
```
