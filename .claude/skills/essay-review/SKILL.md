# 論考・エッセイ レビュアー

著者が練り上げた論考・エッセイ記事を受け取り、以下の観点で評価・改善提案を行います。

このスキルは技術記事レビュー（`/article-review`）とは別物です。評価軸は「技術的正確性」ではなく「著者の声が宿っているか」「読者が共感できるか」です。

## 使い方

レビューしたい記事の内容を貼り付けるか、ファイルパスを指定してください。

---

## レビュー観点

以下の5つの観点で評価し、それぞれスコア（5段階）と改善提案を出してください。

### 1. 著者の声・パーソナリティ (/5)

- 著者自身の経験・現在地への言及（自己開示）があるか
  - 例：「僕もこの恩恵に預かっている身だから」「実際僕も〜な毎日です」
- 具体例が著者の実務経験に根ざしているか（一般的な科学比喩だけで流れていないか）
- 記事のコンセプトとそぐう形で、著者のキャリア形成から生まれた固有語彙の選択やフレームワークが思考の道具として機能しているか
- 「誰でも書けるデータサイエンティスト・データアナリスト論」になっておらず、著者のパーソナリティが感じられるか

### 2. 論理的整合性 (/5)

- 記事全体として論理的・合理的で矛盾がないか
- 冒頭で提示した問いや主張に記事が最後まで答えているか
- 論の飛躍・前提の省略が読者を置き去りにしていないか
- 各節が次の節への橋渡しになっているか

### 3. 共有了解の可能性 (/5)

想定読者はデータ分析を仕事にしている人（同業者）とAI活用を模索しているビジネス職。

- 読者が「わかる」ではなく「そうだ」と感じられる具体性があるか
- 「AIはすごいが人間も大切」のような曖昧な落とし所に逃げていないか
- 一般論の要約・まとめになっておらず、著者の視点が入っているか
- 同業者（データアナリスト）に強く刺さり、ビジネス職には「新しい視点」として機能しているか

### 4. 文体・リズム (/5)

- ます調基調で、断言と問いかけのバランスが取れているか
  - 断言例：「〜にある」「〜からしか生まれない」
  - 問いかけ例：「〜ではないでしょうか」「〜だと思いませんか」
- 長文で論理を積み上げた後、短文で封をするリズムがあるか
- 「僕たち」で読者を傍観者にせず論に引き込めているか
- 馴れ馴れしくない自然なトーンか（「〜なりましたね」のように読者の感情を先回りしない）

### 5. 締め括りと参考資料 (/5)

- 締め括りが力強く、記事で一番言いたいことで終わっているか
- 「僕はそう考えている」など個人の確信として引き取れているか（曖昧な着地になっていないか）
- 参考資料セクションが末尾にあるか

## 出力形式

```
## レビュー結果

| 観点 | スコア | コメント |
|------|--------|----------|
| 著者の声・パーソナリティ | x/5 | ... |
| 論理的整合性 | x/5 | ... |
| 共有了解の可能性 | x/5 | ... |
| 文体・リズム | x/5 | ... |
| 締め括りと参考資料 | x/5 | ... |
| **総合** | **x/25** | |

## 強み
- [記事の良い点]

## 改善提案（優先度順）

### 高優先度
1. [最も重要な改善点と具体的な修正案]

### 中優先度
2. [改善できるとよい点]

### 低優先度（任意）
3. [あると良いがなくても問題ない点]
```

---

レビュー完了後、「この記事を `/write-article` で修正版を生成しますか？」とは案内しないこと。論考・エッセイは著者自身が練り上げる作業が本質であり、Claudeが修正版を生成することは想定していません。改善提案を参考に著者が自分で推敲することを促してください。
